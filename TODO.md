### 🐞 2.1. Критический сбой Peewee: обращение к несуществующему полю `Group.username`

* **Файл**: `database/group_user_database.py` (строки 49 и 100).
* **Симптом**: `AttributeError: 'Group' object has no attribute 'username'`.
* **Где стреляет**:
    1. При нажатии кнопки «🌐 Ссылки для отслеживания» (`handlers/user/get_dada.py:148`).
    2. При проверке каналов перед запуском парсера (`account_manager/parser.py:585` и `parser.py:758`).
* **Причина**: В модели `Group` поле объявлено как `username_group = CharField()`, а в коде функций
  `get_user_channel_usernames` и `get_user_channels_or_notify` написано:
  ```python
  # Строка 49:
  usernames = [row.username for row in records]  # ОШИБКА: должно быть row.username_group
  # Строка 100:
  channels = [group.username for group in Group.select().where(Group.user_id == user_id)]  # ОШИБКА
  ```
* **План отладки**:
    1. Заменить `row.username` на `row.username_group` в `database/group_user_database.py` (строки 49 и 100).
    2. Проверить функцию `dell_group` на корректность имени поля в фильтре Peewee.

### 🐞 2.2. Падение парсера и удаления каналов при невалидной Telethon-сессии

* **Файлы**:
    * `account_manager/parser.py` (строки 752–755).
    * `handlers/user/delete_group_from_database.py` (строки 94–96).
* **Симптом**: `AttributeError: 'NoneType' object has no attribute '...'`.
* **Причина**: Метод `checker.client_connect_string_session(...)` возвращает `None`, если сессия не авторизована
  (`is_user_authorized() == False`). Последующий код вызывает методы клиента без проверки:
  ```python
  # parser.py:
  client = await checker.client_connect_string_session(accounts[0]['session_string'])
  active_clients[str(user_id)] = client
  already_subscribed = await sync_account_channels(client)  # Падает, если client is None!
  
  # delete_group_from_database.py:
  client = await checker.client_connect_string_session(accounts[0]['session_string'])
  await unsubscribe(client, group_username)  # Падает, если client is None!
  ```
* **План отладки**:
    1. Добавить проверку `if client is None:` сразу после вызова `client_connect_string_session`.
    2. Отправлять понятное уведомление пользователю (`t("account_auth_expired")` или аналогичное).
    3. Помечать или удалять невалидную сессию из БД (`UserAccountsTable`).
    4. Корректно завершать выполнение без вызова исключения.

### 🐞 2.3. Зависание сессии: незакрытый `disconnect()` в хендлере удаления

* **Файл**: `handlers/user/delete_group_from_database.py` (строка 98).
* **Симптом**: Предупреждение `RuntimeWarning: coroutine 'TelegramBaseClient.disconnect' was never awaited`. Соединение
  с Telegram остается открытым в памяти.
* **Причина**:
  ```python
  client.disconnect()  # Вызвано синхронно без await!
  ```
* **План отладки**:
    1. Заменить на `await client.disconnect()`.
    2. Обернуть в блок `finally:` для гарантированного отключения клиента даже при возникновении ошибок.

### 🐞 2.4. Рассинхрон формата ссылок: сохранение vs удаление каналов

* **Файлы**:
    * `account_manager/utilit.py` (`normalize_telegram_link`).
    * `handlers/user/settings_handlers/connect_group.py`.
    * `handlers/user/delete_group_from_database.py`.
* **Симптом**: Канал невозможно удалить из БД через меню «Удалить группу», бот пишет, что группа не найдена.
* **Причина**:
    * `normalize_telegram_link` сохраняет ссылки в БД в виде полного URL: `https://t.me/channel_name`.
    * При удалении хендлер ищет по введенному тексту (например `@channel_name` или `channel_name`):
      `Group.delete().where(Group.user_id == user_id, Group.username_group == username)`.
    * Из-за несовпадения строк `https://t.me/channel_name` != `@channel_name` удаление не срабатывает.
* **План отладки**:
    1. Привести хранение к единому формату: либо канонический юзернейм `@channel_name` (без URL-префиксов), либо
       нормализовать ввод пользователя перед удалением через ту же функцию `normalize_telegram_link`.
    2. Добавить обработку приватных инвайтов (`joinchat` / `+hash`), чтобы они сохранялись корректно.

### 🐞 2.5. Риск падения парсера из-за отсутствия `target_group_id`

* **Файл**: `account_manager/parser.py` (строка 813).
* **Симптом**: При попытке переслать сообщение `target_group_id` равен `None`, сообщение не отправляется или падает
  логгер.
* **Причина**:
  ```python
  target_group_id=get_group_id_with_personal_tracking(str(user_id))
  ```
  Если пользователь запустил отслеживание, но ещё ни разу не заходил в модуль `personal_tracking` (где создается
  супергруппа), в таблице `personal_tracking` нет записи для данного `user_id`.
* **План отладки**:
    1. В `parser.py` перед стартом фонового слушателя проверять наличие `target_group_id`.
    2. Если группа отсутствует: либо вызывать процедуру автосоздания группы на лету, либо останавливать запуск и
       выдавать пользователю инлайн-кнопку «📢 Создать группу уведомлений».
    3. Удалить закомментированные куски старого кода с `GroupModel` и `group_model` (строки 77–89, 773–801), засоряющие
       файл.
